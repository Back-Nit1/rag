  no events. This is documented in a comment, so two similar events make the API
  ask.

  `state.get(user_id, …)`.

  `blocking=False` and `candidate_ids`. Nothing is mutated.
    - Registered sets the event to registered and marks its open registration
  tasks done with `completed_at`. A task target resolves to its event first; a
  task with no `event_id` is just marked done.
    - Canceled sets the event's attendance to canceled, or the task to canceled
  with `canceled_at`.
    - All writes use `tx.put` with `expected_revision` from the current row.
  - **Linked tasks:** registration and prep tasks created from an event intent
  now carry `event_id` and `purpose`. The registration task's reminder is
