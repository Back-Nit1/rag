## Decisions recorded this session

1. **mypy checks production sources only.** `/tests/` is excluded; production
   strictness is untouched and all 103 production errors were fixed rather
   than suppressed. Full reasoning and the three narrow exceptions are in
   `docs/architecture/0003-typing-and-lint-scope.md`.
2. **`ErrorCode.LIMIT_EXCEEDED` is part of contract v1**, mapped to HTTP 413
   and documented as distinct from `UPLOAD_TOO_LARGE` (stored bytes). Four
   production call sites already raised it; the member did not exist, so each
   would have raised `AttributeError`. There was never a duplicate `ErrorCode`
   definition in the tree — the drift was contract vs. call site, and
   `FailureCategory.LIMIT_EXCEEDED` is the likely source of the confusion.
3. **`MemoryStore.query` returns `(memory_id, score, metadata)`**, not hydrated
   `Memory` objects. Both implementations already did this and the caller
   hydrates from authoritative state, which is what stops a stale or
   cross-tenant index entry reaching a prompt. The port was wrong and was
   corrected, not the implementations.
4. **The adapter seams are typed against the ports.** `Adapters`,
   `DispatchContext` and `RequestContext.state` carry protocol types. This is
   load-bearing: it is the mechanism that makes drift a type error. It found
   nine undeclared `StateStore` methods. Reverting any of them to `Any`
   re-opens that class of bug.
5. **The SQS outbox batch is always reported fully consumed.** Retry state is
   the outbox row (`state` + `available_at`), so redelivery would duplicate a
   trigger rather than recover a failure. The previous docstring claimed
   partial batch failure reporting that the code never did.
